# 固件与嵌入式分析

固件是「容器套容器」：先拆开外层，再判断每个区域属于什么，最后才分析代码。跳过拆解直接找字符串，得到的结论通常站不住。

## 分类与拆解

1. 先看文件头与尺寸规律：常见的有厂商自己的包格式、带签名的更新包、直接在某个偏移上追加的 SquashFS/JFFS2/UBI/cramfs，以及裸镜像。
2. 熵分布与可打印串分布帮助定位加密区、压缩区与未压缩代码。
3. 用 `inspect_firmware_regions` 得到区域划分；需要真正解包时用 `extract_firmware`，输出目录由用户指定为新的绝对路径，本产品不会替你选位置。
4. 逐层记录：偏移、长度、格式、识别依据（magic、熵、可解析的文件系统）。识别失败就写未知，不要强行套一个格式。

解包依赖 Binwalk 或 Unblob，且需要 Linux 环境；缺少工具时说明前提，而不是假装做完了。

## 找出真正的系统

拆开后定位内核（zImage、uImage、bzImage、ELF）、rootfs、init 脚本、服务与配置。rootfs 里最值得先看的通常是：`/etc/init.d`、systemd unit、`rcS`、启动的守护进程、内置的 Web 管理接口、默认凭据、硬编码的地址与端口。

内核模块的元数据（`.modinfo` 键序、`__versions` CRC、签名 trailer）用系统工具或 `list_strings`／`read_bytes` 读；`inspect_binary_layout` 给出段与重定位的确切范围。读到的签名值不构成验证结论，`struct module` 也不在解码范围内。

## MCU 与裸机

没有 ELF 头的镜像要靠入口约定找起点：ARM 的向量表（初始 SP + 复位向量）、MIPS 的 jump target、以及中断向量表布局。从字面池和外围基地址反推内存映射，再用字符串与库指纹识别 RTOS（FreeRTOS、Zephyr、RT-Thread）或裸机循环。定位主循环、任务创建点和外设驱动（UART、SPI、I2C、无线栈），把它们对应到函数地址。

## OTA 与信任链

更新路径是固件分析里最有价值的部分之一：下载地址、传输协议、签名与校验的实现位置、写入目标分区、失败回滚。找到校验函数后说明它检查了什么、用什么密钥、校验失败后的行为。凭据类材料（默认口令、调试 token、私钥）只报告存在与位置，不在报告里大段粘贴私钥。

## 边界

静态分析优先，不要刷写设备、不要连接不属于用户的生产设备、不要向设备发送构造的固件。需要运行时验证时，先和用户确认目标设备属于他自己。

## 输出

镜像身份与哈希 → 容器与分区图 → 各区域格式与识别依据 → 系统与服务清单 → 与问题相关的实现路径 → OTA 与校验结论 → 未知区域与下一步需要的条件。
