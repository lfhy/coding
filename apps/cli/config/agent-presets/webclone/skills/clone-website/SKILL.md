# 复刻一个网站

在本地把用户给的页面重建出来。先对齐源站，再谈新的设计方向。交付物是可运行、可编辑的代码；截图、iframe 与下载到的生产构建只是参考，不是实现。

## 1. 排期与映射

先读项目说明、真实的框架与脚本、既有路由，再打开源站。能用直连 HTTP、资产工具或接口取到的内容优先直连，浏览器用来确认外观与行为。

写一份简短的「源址 → 本地路由」映射，以及每个页面归属哪些文件。跟工程既有约定走；采用上游模板作地基时用 `src/app/`、`src/components/sites/<site>/`、`public/sites/<site>/`、`docs/research/<site>/`，别的栈用该栈自己的目录并在调研目录记录。来源、页面与下载物各用可读且互不冲突的名字；重名时加端口或 URL 片段。

- 第一次复刻根路径时，可以替换模板自带的空白首页。
- 同一来源的多个页面保留源站路径名。查询串／锚点差异通常只是同一路由的状态，把这些状态复现出来，不要各建一个页面。
- 保留工程里已有的页面与资源。用户要求时才改；请求范围外的路由冲突先解决再替换任何东西。
- 给已有复刻结果加页面时，扩展它的布局与全局样式，不要替换既有页面在用的样式。
- 不同来源默认各用一个应用，除非用户要合并。合并站点要有各自的路由前缀与作用域化的字体、样式和布局。
- 与框架语法冲突的字面路径段（`_`、`@`、方括号、圆括号）用框架支持的机制转义，再验证真实请求的 URL 能打开。

既有复刻结果是好起点：拿它跟当前源站比一遍，记录哪些可以复用。所有请求的 URL 都有落点、每个页面归属清楚，这一步才算完。

## 2. 先观测再动手

桌面与移动宽度都要整页看过。从头滚到底，让懒加载媒体就位、粘性／固定场景完整露出。然后逐个操作菜单、标签页、手风琴、轮播、悬停态与主要链接。要分清变化由**滚动、点击、悬停还是时间**驱动——用点击模仿滚动驱动的区块，得到的是另一个产品。

把每次观察当作一条**规则**的样本。读声明值（计算样式、CSS 变量、库的实时选项），不要只凭某一次渲染反推；变换视口宽度（包括比设计稿更宽）、视口高度、输入方式与状态，直到弄清是什么在驱动变化。用访客真实使用的输入驱动页面（滚轮、触摸、键盘、指针）；脚本滚动会绕过挂在滚动上的行为（例如平滑滚动）。

保留源站截图，标注视口、滚动位置与交互状态。捕捉替代状态下的内容与资产。每个页面写一份紧凑的页面简报：区块顺序、排版、布局量测、资产映射、交互。需要独立协作者时再加分区简报。

资产提取、状态对比与量测字段清单见 `website-inspection` 技能。遇到 **Framer 生成的页面、粘性场景、入场动画或动态媒体**时，再加载 `framer-and-motion`。

用源站的真实文案与它实际加载的文件：字体、图片、SVG 与视频。换成同名但来自别的厂商或图标集的资产，度量与形状都会不同。重要的几何与计算样式要量。把分层的图片与媒体元素先看清楚，再决定是否用 HTML 重建。维护「源 URL → 本地资产路径」记录，核对内容类型与尺寸：`.png` 的 URL 可能返回 AVIF。

每个区块与有意义的状态都有足够证据、无法获得的部分被明确标注，这一步才算完。大段 DOM 导出不能替代真正看页面。

## 3. 首轮就做完整

先立字体、页宽、颜色、资产、路由、整页行为与共享组件。共享组件一次把所有观测到的状态（悬停、聚焦、断点）都建出来，后续复用它即可。优先复用合适的既有组件。布局与简单动效用 CSS，源站行为需要时再上动画库。

用真实内容搭出连贯的区块。共享文件有人负责之后，可以按页面或区块委派独立工作。给协作者截图、相关量测与状态说明、资产路径、目标文件与明确的完成线；一份带精确文件引用的简短简报就够，不需要固定的协作者数量或逐组件的文书。

复现范围内的交互。保留真实的外链目标；被纳入范围的目标改成指向本地路由，范围外的目标仍指向源站并在交付时说明。可见的控件必须真的做它承诺的事。

一个完整切片之后就运行工程对应的检查。每个请求的区块／路由都能用真实资产渲染、重要控件可用，这一轮才算完。

## 4. 对比、修复、重复

源站与本地页在**相同视口、相同滚动位置、相同状态**下打开。等字体、媒体与入场动画稳定。凡是第 2 步发现「规则会变化」的位置都要整页复核，再加一个比设计稿更宽的视口；滚动与指针行为用真实输入判断。并排拼图定位偏移，整幅分区截图确认细节。

按可见差异从大到小修：几何、缺失的区块／图层、排版与换行、资产裁切，最后是间距与动效。改完再复查受影响的视图。有动效的区块比较初始、进行中与稳定三态，必要时反向滚动再比一次。

跑真实本地流程：克隆路由之间的跳转、移动端菜单、标签页／手风琴状态、轮播边界、主要动作、媒体控件与观测到的滚动联动。检查运行时报错、缺失资产与横向溢出。加了页面要确认既有路由仍然可用。这些边界用几次真实浏览器检查，而不是断言 class 名。

跑工程的生产检查。完成要求同时有**成功的构建**与**渲染对比**；未验证的结果不要称作像素级一致，把剩余差异写清楚。

## 交付

给出预览与运行方式、「源址 → 本地路由」映射、有代表性的桌面与移动对比、实际跑过的检查，以及剩余的视觉与功能差异。维护可复用的模板时，参考用的复刻结果放在独立应用里。

需要登录才可见的页面，按提示词里的登录续期规则处理：把登录页开在 Agent 浏览器里，请用户在右侧面板本人完成登录（扫码或人机验证时让用户点面板上方的「在浏览器窗口中打开」），确认后复核页面再继续。不要索取凭据，也不要让用户把 Cookie 或 token 粘进对话。
