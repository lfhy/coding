# Agent Note: 文档采用中文单文件并保留历史配对兼容

Status: implemented

## 问题

仓库把每次文档编辑都扩展成英文、中文和伴随记录三件套更新。即使功能实现已经完成，一个很小的说明改动也需要读取翻译规范、更新对侧文件、重录 blob hash，并等待配对检查；大段文档若由主任务直接处理，还会长期占用实现上下文。产品 UI 与 locale 字典确实需要运行时 i18n，但这不等于开发文档必须承担同样的双语维护成本。

历史语料已经包含大量有效配对。一次性删除全部英文或中文文件会制造与当前功能无关的大型 diff，并同时影响文档站、生成器和冻结决策记录，因此新流程必须允许它们在未触及时继续存在。

## 决策

无语言后缀的 `.md` 是普通仓库文档与新 Agent Note 的中文 canonical。新增文档只创建这一份文件；实质修改普通 legacy pair 时，默认把 `.zh.md` 内容迁入无后缀文件，并删除语言切换行、`.zh.md` 与 `.i18n.yaml`。产品 UI 文案、locale 字典、协议 locale 和系统 i18n 继续由产品代码自己的契约管理，不属于文档单语化。

`verify-translation-pairing` 从「所有范围内文档必须配对」改为「出现配对产物就严格验证」。发现以现存 `.zh.md` 或 `.i18n.yaml` 为锚点：任一产物存在时，三件套必须完整、hash 必须匹配、切换行与结构必须一致；只有 `.md` 的中文单文档不进入状态表，也不产生 `missing`。这保留了[历史配对与 blob 恢复机制](2026-07-02-bilingual-docs-and-pairing-gate.md)的有效部分，同时取代其中的全语料统一要求。

现有未触及的配对不做全仓迁移。由生成器固定输出语言、文档站仍明确发布双语，或用户显式要求保留的配对可以继续使用旧门禁和[轻量更新机制](2026-08-08-lightweight-routine-documentation-translation.md)。翻译提示词的校准金标改用冻结 fixture，避免当前政策文档的调整无意改变模型提示词快照。

Agent Note 格式门禁同时接受两种 canonical：历史英文 `.md` 继续使用英文章节名，新中文 `.md` 使用 `问题／提案／决策／曾考虑的替代方案／验收标准／风险／后果`。分类仍由路径决定，不依赖正文语言。归档门禁接受新的中文单文件或完整历史三件套，并对两种形态继续执行追加封存。

可与功能实现解耦的文档编写、迁移和大段编辑优先委派为独立子任务。主任务负责给出事实边界、禁止触碰的产品 i18n 范围和验收命令，再核对结果；不再让翻译和配对维护阻塞功能实现。

按 `git ls-files` 遍历仓库内容的机械工具必须跳过工作树中已删除的 tracked 文件。单文档迁移会在提交前留下合法的 `.zh.md`／`.i18n.yaml` 删除项；同步或重写工具不能因为索引仍列出这些路径而在读取阶段失败。

## 验证

`verify-translation-pairing` 证明所有仍存在的 legacy pair 完整且一致；`verify-agent-note-classification` 与 `verify-agent-note-format` 证明中文单文件 Agent Note 进入正确目录并满足中文骨架；`verify-md-links` 证明删除 `.zh.md` 后没有悬空链接；`verify-doc-budgets` 和 `git diff --check` 继续约束文档规模与补丁卫生。产品 locale 测试不因本流程变更而删除或放宽。

## 曾考虑的替代方案

**一次性删除全仓所有英文对侧与伴随记录。** 不采用。它会把历史清理、生成器迁移、文档站路由和当前功能改动混在一个不可评审的大型 diff 中；按触及范围渐进迁移即可消除日常成本。

**完全删除配对门禁和翻译工具。** 不采用。未迁移的历史三件套仍需要检测单边漂移、破损 sidecar 和合并冲突，用户也可能显式要求维护某个配对。把门禁改成产物驱动即可保留这些能力。

**继续要求双语，只把翻译委派给 subagent。** 不采用。委派能释放主任务上下文，却不能消除额外文件、翻译质量评审、hash 重录和 CI 扫描成本；它只改变成本由谁承担。

**保留英文 canonical，仅删除中文对侧。** 不采用。项目的维护者与用户已经选择中文作为开发文档默认语言，继续以英文为真源会让日常编辑仍需先翻译自己的意图。

## 后果

普通文档改动只需要维护一份中文文件，流程不再自动加载术语表、翻译 skill 或配对重录。历史配对仍可能在一段时间内与中文单文档并存，因此看到 `.zh.md` 不能推断所有文档都必须配对；是否受配对门禁约束由配对产物本身决定。

迁移一个历史配对会删除其英文正文，放弃英文读者的同步版本；这是降低个人客户端维护成本所接受的取舍。需要英文版本的具体文档仍可由用户显式要求保留或重新建立配对，但这不再是仓库默认义务。
