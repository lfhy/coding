# Agent Note: 桌面 Remote-SSH 是有界工具网关

Status: implemented

[English](2026-08-30-desktop-remote-ssh-tool-gateway.md) | 中文

## 问题

Workspace 选择器提供了远程导航，却无法在保留本地 Coding Host、Session 日志、凭据、设置和 UI 的同时打开远程目录。把完整 Host 放到远端会拆分本地产品状态，或要求第二套部署。若把一个小型 SSH 辅助程序当成完整远程执行提供方，则会产生另一项缺陷：文件系统路径、子进程、PTY、语言服务器和 Code Mode 看起来共享一个执行世界，但实际只有部分操作移到了远端。

## 决策

Coding 桌面端提供有界 Remote-SSH 工具网关。选择器为当前连接收集一次密码或私钥，依据应用私有 `known_hosts` 校验主机，部署小型 Go agent，并让用户选择远程目录。agent 只监听远端回环接口；桌面进程通过经过认证的 SSH 连接访问它。浏览器只会得到每窗口的 Wails 能力 token、连接进度、主机密钥确认元数据、目录列表和不敏感的连接 id。待确认主机密钥只保留公钥和目标身份，绝不保留密码或私钥。

选择目录会在 `DSH_HOME` 下创建本地 marker。其目录名由 SSH 目标身份和规范化远程路径的摘要组成，因此重新连接同一目标会用新的内存连接 id 重写同一个 marker，并以幂等方式解析既有 Workspace。marker 不保存地址或认证材料，并会持有其选定的连接，直到 marker 被重新绑定或桌面端关闭；关闭请求不会让 marker 指向陈旧 id。连接和 id 只在当前进程中有效：桌面端重启后，打开既有远程 Workspace 会快速失败，直到用户再次执行连接 Remote-SSH。Coding 不会持久化凭据，也不会在后台重新连接。

桌面端启动回环 HTTP bridge，使用与 WebView token 不同的 token，并仅通过环境变量把 URL 和 token 传给本地 Node Host。已经运行的共享 Host 无法取得这项瞬时能力，因此桌面端启动时会先替换兼容的受管 Host，再进行连接。bridge 只接受固定的路由和方法允许列表、有界请求体、已知连接 id，以及经过认证的回环请求。

当前网关刻意小于可移植执行世界约定：

- `dsh-fs-local` 会为语义文件操作识别 marker。每个 agent 请求都携带选定的远程根；agent 解析现有符号链接或最近的现有祖先，并拒绝根外路径。当消费方请求本地进程路径或 `file:` URI 时，远程目标会快速失败。
- `dsh-fs-sandbox` 保留 `read-only`，把 `workspace-write` 约束到调用 Session 映射后的远程子目录，并且只在 `danger-full-access` 下允许不受约束的变更。
- `dsh-bash-local` 会把 marker cwd 发起的前台 Bash 调用路由到 agent。模型提供的相对 workdir 必须仍位于同一 marker 下；否则工具会在任何本地或后台进程启动前拒绝该调用。`dsh-bash-sandbox` 只在 `danger-full-access` 下允许该路由，因为本地 OS 沙箱无法约束远程 Shell。
- 后台 Shell 句柄、PTY、持久终端、文件系统搜索子进程、LSP 和专用远端 Code runtime 均未实现。这些进程能力会失败，不会在本机运行，也不会声称具备远程生命周期保证。隔离的 Code worker 仍在本地运行，可以编排已支持的远端文件系统与前台 Bash binding。

远程变更会在发布开始前检查取消，随后等待 agent 的确定响应，不会在提交可能已经发生后中止传输。请求和完整响应上限会计入 JSON/base64 或 before/after 包装，因此已经提交的变更不会仅因确认响应大于请求而被重新归类为传输失败。

本决策只取代[工作区选择器提供本地、远程与无项目入口](2026-08-25-workspace-picker-local-remote-and-no-project-entry.md)中的地址导航分支。该记录仍拥有三项 Hero 操作布局和无项目行为。本决策不会取代[文件系统与子进程执行世界之上的可移植消费方](../architecture/2026-07-28-portable-execution-world-consumers.md)：本网关明确不会把自己呈现为该 seam 的成对提供方。

## 考虑过的替代方案

**导航到单独可达的远程 Host。** 未将其作为唯一桌面路径，因为它会改变 Session、设置和凭据的所有者，而不是在当前本地产品中打开远程目录。在本选择器流程之外，独立部署的 Host 仍是有效部署方式。

**立即实现完整远程文件系统／子进程提供方对。** 延期处理，因为诚实的功能对等需要普通进程发布、流式输出、进程树级取消与完全停稳、可执行文件查找、PTY 分配、文件 URI、LSP，以及其他所有通用消费方。有界网关会让不支持的消费方快速失败，而不会近似实现这些约定。

**持久化 SSH 凭据以自动重连。** 本轮未采用，因为这需要凭据引用格式、OS 密钥存储所有权、轮换与吊销行为，以及启动重连状态机。手动重连牺牲便利性，换取更小的持久安全面。

**安装 Node 并宣称提供远端 Code runtime。** 未采用，因为检测或安装 Node 不会移动 worker 运行时及其回调协议。Code Mode 仍在本地隔离 worker 中运行，可以编排已支持的远端 binding；通用远程进程执行与取消则需要真实的同执行世界提供方。

## 后果

远程文件编辑和前台 Bash 无需在目标上安装 Node，同时本地 Host 仍是产品状态的唯一所有者。系统会拒绝已变更的主机密钥，要求显式确认未知密钥，从远程命令中清除环境里形似凭据的变量，并阻止远程路径通过词法遍历或符号链接越过选定根目录。

桌面端启动时会先替换兼容的受管 Host，使其继承瞬时 bridge。既有浏览器会短暂失去该 Host，远程 Workspace 在桌面端重启或 SSH 断开后需要手动重连。不支持的执行世界消费方会保持为可见限制，不会静默操作本地路径。已上传 agent 的清理、持久凭据引用、自动重连和完整远程提供方对仍属于后续独立决策。

聚焦 TypeScript 测试覆盖 marker 校验、bridge 认证与响应上限、远程文件／二进制操作、变更取消、沙箱子目录约束、Bash 路由和不支持的后台执行。Go 测试覆盖严格协议解码、根与符号链接约束、进程／环境处理、不保留凭据的主机密钥确认、bridge 与 Wails binding、连接清理、确定性 marker 重绑定，以及打包产物选择。桌面构建会打包每个受支持的 agent 目标；Web 场景固定 Remote-SSH 入口，组件测试则固定向导可见文案。
