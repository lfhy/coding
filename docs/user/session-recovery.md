# 会话历史恢复

会话日志按连续的 `seq` 保存事件；它是对话历史的来源，设置中的元数据缓存不是备份。历史加载失败弹窗会显示实际错误和代码，请先记录该信息，不要直接归档或改写日志。

## 自动恢复

冷会话存在未闭合轮次时，Host 保留已经写入的事件，补写尚缺的工具结果、步骤和 `turn/end { interrupted }`，再允许继续使用。撕裂的最终记录只有在能够证明它未提交时才可截断；已经提交的事件不会因为恢复而被丢弃。仍有写入者的会话不能由另一个 Host 当作冷会话恢复。

## 元数据重建

本机设置中的「修复会话元数据」从持久日志重新计算会话列表等派生缓存，不更改会话日志。它跳过正在运行的会话，并逐一报告无法读取的日志；它不能修补已提交的序号缺口、重复序号或损坏的压缩帧。操作完成后重新打开会话以刷新显示。

## 日志无法加载

序号倒退或缺失、已提交区域中的解析错误，以及不受支持的格式都不能通过缓存重建解决。先退出所有可能写入该数据目录的 Coding 窗口和 Host，再备份**整个**会话目录，包括 `session.jsonl.zstd`（或未压缩的 `session.jsonl`）和其他会话产物。默认目录是 `~/.coding/sessions/<项目目录>/<会话 id>/`；显式设置 `CODING_HOME`／`DSH_HOME` 或尚未迁移的旧安装可能使用其他根目录。

在备份上核对原始帧和事件，再决定是否修复原件。不要仅凭错误中的 `expected`／`got` 数字改写 `seq`、删除任意行或复制会话 id：相同序号可能包含不同的用户、模型或工具事实，直接去重会丢失内容。无法证明无损时保留原件，使用备份或寻求人工恢复；归档只隐藏列表项，不删除原始日志。
