# 会话历史损坏

会话日志按连续的 `seq` 记录持久事件，序号缺口意味着已有事件丢失。Host 只有在能够证明缺口之后的数据尚未提交时才会自动截断，除此之外一律拒绝加载并保留原始文件。

## 自动恢复

最终记录没有形成已提交的 `turn/end` 时，抛出的尾部属于写入过程中的残留：加载会把日志收敛到最后一条完整事件并补写轮次结束标记。原始已提交前缀不被改写。

## 无法自动恢复

已提交区域内的缺口或乱序无法通过截断修复——缺口之后可能仍有已提交的模型与工具事实。此时加载会失败，客户端显示中文错误提示。恢复方式：

1. 关闭正在写入该会话的窗口，避免它继续追加。
2. 备份整个会话目录（`$DSH_HOME/sessions/<项目目录>/<会话 id>/`），包括压缩日志。
3. 在备份上确认缺失或重复的记录；确认无损后再替换原文件，或按备份内容重建会话。

不要手工删除任意行、改写 `seq` 或复制会话 id：重复的 id 会让加载直接拒绝。

## 冲突解决会话

Git 拉取冲突的“新建会话解决冲突”创建新的空白会话，优先复用当前会话所属的工作区；未归属工作区时在 Host 用户 HOME 创建未分组会话。它不 fork 当前会话，因此空白会话和没有完成轮次的会话也可使用。

## 会话处理

归档会话（侧栏行菜单）会把它从工作区和未分组列表隐藏，同时保留日志与工作区账目。当前客户端不提供永久删除：需要保留证据时归档，需要彻底清理时在关闭服务后删除会话目录。
