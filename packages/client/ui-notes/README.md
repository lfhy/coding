# coding-client-ui-notes

笔记界面：外侧窄导航的「笔记」入口、独立主内容页，以及完全复用对话的 AI 助手栏。

## 页面结构

独立主内容页（`shell.page` 的 `notes` 键）占满侧栏右侧的全部主内容，自身在 `.pageMain` 内做三分区：目录树侧栏 | 原始文本编辑 | Markdown 预览。根布局的 AI 助手轨（`ctx.layout.setPageAssistant`）把 `conversation` slot 渲染进同一主内容的右半区，与页内两块平分，合起来即 1:1:1 的「原文 | 预览 | AI 助手」。页面包不声明任何 `conversation.*` slot，也不实现对话视图。

## 数据源

目录树、原文读写、新建笔记都来自文件库服务持有的笔记域（`packages/attachment/file-library` 的 `~/.coding/files/notes`）。页面包只消费 HTTP 接口（`/api/notes/*`），不直接触碰文件系统。导航流程先取笔记根目录路径，复用工作目录相同的已有会话，否则创建只以笔记根目录为工作目录的会话（对话模式，不挂工作区），再打开页面并挂上 AI 助手轨。因此 AI 助手看到的工作区就是笔记目录：它能读、能改、能新建笔记，界面每 4 秒轮询一次目录树，当前笔记被外部修改且编辑器无未保存改动时静默采用新内容。

## 编辑与保存

编辑器停顿 900ms 后自动保存，`Cmd/Ctrl+S` 与切换笔记、窗口失焦时手动保存共用同一路径。保存携带读取时的修改时间做冲突检测：外部已修改时进入「已被外部修改」状态，编辑器保留未应用的改动，预览区的「重新加载」按钮可放弃本地改动采用磁盘内容。新建笔记通过模态框输入名称，由 Host 净化并补 `.md` 扩展名。

## Model Experience

界面不注入模型可见内容；笔记页的对话与工作台中的对话共用同一会话日志与回放规则。AI 助手对笔记目录的读写走文件工具链的常规路径，不产生新的模型输入。

## 已知限制与后续工作

- 子目录里的笔记只在目录树中可见，不会出现在文件管理的未分组列表（那里只登记笔记根目录的直属文件）。
- 助手栏与页内两块平分主内容区时，窄窗口下三列都会变窄；低于内层 1024px 断点时侧栏自动收成图标轨，编辑与预览列不再单独响应。
