# coding-client-ui-image-gen

图像生成的浏览器界面：设置里的「图像生成」分区、欢迎页和会话页头的画图入口、`image-gallery` 会话视图、以及会话右侧的「AI 画布」标签。界面沿用客户端现有 slot、工作台、图标与主题样式；图像字节、画廊记录和画布文档由 [图像服务](../../image/image-gen/README.md) 持久化。本包是该服务的可选 UI，不装配时不影响其他对话界面。

## 使用与设置

在「设置 → 图像生成」配置 `image-generation` 命名空间。`enabled` 默认 `false`；`endpoint` 和 `model` 默认为空；`apiKeyRef` 默认为 `IMAGE_GEN_API_KEY`。服务地址允许 HTTPS 或本机回环 HTTP，禁止内嵌凭据、查询和片段；`apiKeyRef: ''` 表示本地服务无鉴权。密钥内容只发送到 `credentials.set`，设置镜像只保存引用与 `credentials.describe` 返回的存在性、可写性。地址、模型或所需密钥缺失时开关自动禁用，其他配置字段仍可保存；已保存的启用偏好只有配置完整时才显示为开启。既有画廊图片仍可浏览。服务尚未启动时界面保留可重试的空态与已有记录，不显示原始错误。

右上角画图按钮在没有会话时连接工作区的空白会话；现有空白会话切换成 `image` 预设，已有非空画图会话直接回到画廊。已有非空其他模式的会话会打开新的空白会话，而不会改写它原有的 Agent 预设。只有 Host 确认选择模式后才打开会话及 `image-gallery` 视图，模式切换失败不抢占当前会话。画廊保留下方对话输入框，可描述多张画面给画图模式的模型工具；也提供单图生成和基于旧图编辑的表单。画廊仅在可见时每三秒读取当前会话目录，切走或卸载立即取消旧请求；表单生成成功时立即刷新，因此对话中产生的新图也会出现在画廊。

图库列表拥有独立滚动区域，图片用当前会话的受限地址展示。每次最多增量展示 24 项，滚动到末端继续展示；Host 当前一次返回全量会话目录。每张图片可放入右侧画布：前端只持久化画廊项 id，不存图像 base64。宽屏会话首次进入 `image` 预设时自动打开右侧 `image-canvas` 标签一次，用户关闭后不再次抢占；窄于 1024px 的窗口先显示画廊，用户通过画廊页头「打开 AI 画布」手动进入工作台，再由工作台的关闭按钮返回画廊。窗口放宽后，尚未手动打开过的会话仍可自动打开画布。原生 960×640 逻辑画布会随可用宽度等比缩小，支持画笔、橡皮、清空及图片选取、移动、移除；操作按 revision 顺序提交，遇到并发修改的 409 冲突会停止后续写入，提示刷新，不自动覆盖。

## 对接与限制

界面经同源 `/api/image-gen` 使用 `GET /state?sessionId`、`GET /gallery?sessionId`、`GET /image?sessionId&id`、`POST /generate`、`POST /edit`、`GET /canvas?sessionId` 和 `PUT /canvas?sessionId`。画像由 Host 校验同一会话；canvas 写入携带 `{revision,state}`，文档为 `{version:1,nodes}`。节点按顺序绘制：笔迹为 `{id,type:'stroke',points:[{x,y}],width,color:'ink',erase?}`；图库图片为 `{id,type:'image',imageId,x,y,width,height}`。坐标使用固定画布像素，`erase` 在 2D 绘制中使用擦除合成。画布只保存节点，不上传本地文件或分享跨会话图片。Host 必须限制节点数量、坐标、总字节与原图归属，画廊 API 应进一步支持服务端分页才能避免大历史的全量传输。

## 模型体验

本包不注册模型工具或修改提示词；画图和编辑的模型可见事件由 [图像服务](../../image/image-gen/README.md) 持有。画廊页面的手动生成请求不会新增对话消息。

#### KV Cache 影响

本包没有模型请求，画廊和画布操作不影响 KV Cache；会话输入仍按所选预设的普通模型路径执行。

## Known Limitations and Deferred Work

- 图库 API 暂无服务端分页；视图限制已挂载图片数量，但目录仍全量读取。
- 画布只持久化单页笔迹和画廊图片，不提供复杂图层、无限画布或撤销历史。
