# @deepseek-ai/dsh-client-ui-settings-models

模型设置、视觉理解目标与首次使用模型配置引导插件。设置模态框左侧导航分别提供“模型”和“图片识别 Fallback”，两者沿用[设置外壳](../ui-settings-general/README.md)的统一尺寸与导航：模型分区采用可搜索的渠道中列和右侧渠道详情，窄屏列表与详情可返回切换；图片识别使用独立设置分区，选择视觉理解工具的渠道与模型。首次引导在独立阻断式弹窗中复用模型分区的提供方列表与详情两列，并在底部选择默认模型。模型、图片识别和引导共用一份从 `llm.providers`、唯一 `settings.describe` 镜像和不含密钥值的 `credentials.describe` 联接的快照，不显示路由存活状态，也不回显真实密钥。

模型分节中列与搜索只列出已有生效 profile 的可配置渠道；缺少密钥、目录读取失败或路由不活跃不会隐藏已有渠道，无密钥引用的原生认证配置也会保留。中列唯一的“添加渠道”按钮直接打开居中的自定义渠道表单，填写 Provider ID、协议、端点、至少一个模型和可选的密钥；尚未配置的已安装目录渠道不提供添加入口。`llm-pi-ai` 分节无协议选项、设置只读或尚未就绪时，按钮禁用；首次引导复用相同表单。创建前点击取消、按 Escape 或点击遮罩只关闭表单，不改变当前选中渠道；创建成功后关闭表单并在原有右侧详情选中新渠道。DeepSeek 官方渠道的整个 settings 分节就是 profile，因此默认条目仍可编辑。选择已有渠道后，右侧详情常显密钥、地址与模型目录；删除仅适用于用户层独占的 profile，需在确认框中点名渠道。列表徽标仅根据凭据引用的 `credentials.describe` 回答展示“已配置”，不代表路由存活状态。

首次引导从同一个模型联接快照判断就绪：只有当前 `agent-default-model` 的提供方和模型出现在可启动目录候选中，步骤才直接完成且不渲染。首次判定期间不绘制弹窗，但临时将应用根节点设为 `inert` 以阻断工作台；确认已有可用默认模型后立即解除。候选来自已注册、活跃且配置可用的提供方及其成功读取的模型目录；具名凭据引用必须已配置，没有引用的提供方可使用原生认证。没有可用默认模型时，弹窗保留模型分区的提供方编辑能力，要求先有可用提供方与至少一个目录模型，再在底部选定默认模型并保存；不能跳过，也不能通过遮罩或 Escape 关闭。配置通过 `settings.mutate` 保存，`credentials.set` 仍是唯一的密钥写入。设置只读、凭据不可用或模型目录读取失败时保留弹窗并显示诊断与重试，不能把未知状态当成完成；用户显式重试会先重读共享设置镜像，再重新联接提供方、凭据与模型目录。

每一次编辑都以 `settings.mutate` 的路径 op 落到已存分节上——每个变更字段一条 set、每个清空字段一条 unset、删除提供方行则是单独一条 unset。页面自始至终只持有**脱敏后**的 descriptor，因此它只修改自己看得见的字段，而不重建分节。DeepSeek 的 `models` 是一个按值整体替换的数组：编辑器会显示继承而来的生效模型行，直到第一次模型编辑将完整数组具化到用户层；重置则会取消该覆盖。每个模型行承载模型 ID 与显示名称，其上下文窗口与最大输出 token 数则收在该行的模型设置独立窗口中，使用与 pi-ai 提供方表单相同的字段。两项容量都按数值键入，可带十进制的 `K` 或 `M` 后缀（`256K`、`1M`；`1M` 即 1000K），存储为纯数值，回显时写成能够往返的最短形式。空 ID、重复 ID、显式填写的空名称，以及无法读取、非正数或非整数的容量都会在写入前失败。键入的 API 密钥同样在它自己的字段上被判定：trim 之后必须非空，且每个字符都是可打印 ASCII（`[\x21-\x7E]`）——这正是 HTTP 标头值所能承载的范围，是 `@deepseek-ai/dsh-llm` 中 `normalizeApiKey` 的孪生体，因源码平面分割禁止直接引入而在此镜像。与整行粘贴的 `NAME=value` 环境变量匹配或首尾成对引号包裹的值，会以同一条格式失败被拒绝；这项粘贴行检查只在浏览器中运行，因为 resolver 中的一次误判会连带让环境变量这条路也拒绝该密钥。只含空白的输入框会失败而不是被静默丢弃；留空则完全不是失败：在编辑卡片上意味着保持已存储的密钥，在新建卡片上则意味着以其他方式鉴权。被拒绝的密钥会同时拦截写入与端点探测，因此页面不会白花一次往返去换取字段上已经写明的答案。每次 settings 写入都携带卡片当前的 `revision`，因此来自另一个标签页或对 `settings.yaml` 的外部编辑所产生的并发写入会以 `settings-conflict` 被拒绝；settings 提交成功后，卡片在存储凭据前采用应答的脱敏用户子树与 revision，并同步折入唯一设置镜像；凭据阶段失败时只重试凭据。保存完成后等待目录按新镜像联接，再重挂载当前编辑器，因此下一次本地保存以本次 revision 为基线，而外部并发更改仍被拒绝。删除操作只会在 profile 指向页面派生的 `<ROUTE>_API_KEY` 目标时清除已配置且可写的凭据，随后取消设置 profile；两项操作都具备幂等性，部分失败会停留在点名目标的确认对话框中供重试。环境凭据、自定义引用和无法识别目标的凭据保持不变。页面加载完成后会直接订阅转发的 owner 事件 `settings/document-updated`、`credentials/updated`、`llm/adapters-updated`，以及本地 `connection/reset`，因此外部的 `settings.yaml` 编辑、第二个标签页或 settings 新生的路由都无需轮询即可收敛。

DeepSeek 官方提供方的渠道名称位于 API 密钥旁，在首次引导与模型分节共用的编辑器中均可修改。配置字段为 `channelName`，默认 `DeepSeek`；列表、详情标题与未编辑的名称字段共用可配置目录的生效 `displayName`，保存或外部有效设置更新会同步显示名称。只有用户编辑过名称时，提交才去掉首尾空白并写入覆盖；空白或去掉首尾空白后超过 64 个字符的值会在字段旁提示而不写入，显式输入 `default` 也是合法名称。只编辑密钥或地址不会写入或规范化名称。该名称仅是单一渠道的显示元数据，不会创建新路由，也不改变 `deepseek-official` 或凭据引用 `DEEPSEEK_API_KEY`。

## 模型列表与端点询问

模型页的渠道列表提供搜索、选中和自定义渠道创建入口，居中表单直接收集创建所需的配置。所选详情常显凭据与 API 地址；真实密钥只经凭据服务写入，已存值只显示“已配置”。没有验证请求契约，因此页面不提供伪造成功状态的“检测”按钮。首次使用弹窗复用这份渠道列表、创建表单与详情编辑器。

从手工添加或端点目录导入的模型会明确声明文本与图片输入，以及渠道允许的推理档位：DeepSeek thinking 禁用时只有 `off`，其余情况下默认 `off`、`low`、`high`、`max`。模型目录以对齐的模型 ID、模型名称、视觉和推理列显示各行，不套装饰性外卡片；后两列用状态图标区分已声明支持、不支持或未声明。行尾图标打开屏幕中央独立的“模型设置”窗口，窗口自带取消和保存，不插入模型行或改变表格布局。视觉与推理是带可访问按下状态的亮暗图标开关；开启推理后，共享悬浮菜单提供多选档位，触发框显示已选档位。窗口内的保存仅把本行改动纳入提供方草稿，取消或关闭则丢弃；提供方表单保存后才写入设置。详情区较窄时，表头和模型行一起横向滚动。DeepSeek 模型未单独声明推理档位时按渠道策略显示继承状态，pi-ai 缺少能力元数据时不推断。已有模型的未知字段保留。端点发现协议只返回 ID、名称与可选容量，无法给出真实能力类别；发现弹窗仅按模型 ID 家族分组并支持搜索、逐项或整组导入，不按猜测提供“视觉／推理”等分类筛选。导入只修改当前草稿，保存仍由所属设置分节的 revision/path-op 写入完成。

图片识别分区在 `vision-understanding` 分节可用时显示目标选择；候选只来自 `llm.models` 中已配置、可用且明确声明 `inputModalities` 含 `image` 的模型。默认不选，选择或清空都以同一次 `settings.mutate` 对 `provider`、`model` 成对写入或删除，带该分节 revision，并将应答折回共享设置镜像。已保存但不在当前候选内的目标会显式保留供清空或替换；目录整体读取失败或已配置可用渠道逐项失败时保留渠道、已存目标及其他渠道成功返回的候选，展示诊断和重试，且不推断已存目标不可用。不可用渠道的目录失败不影响视觉目标。只有成功读取后没有候选才显示空候选提示。只读、整体加载失败和分节缺失也有可见状态。纯文本模型遇到图片时使用该路由生成描述；未配置路由会提示不支持，不把模型 ID 或端点发现结果当成视觉能力证明。

pi-ai profile 的 `models` 列表在提供方详情中编辑：一行一个模型，行尾的模型设置与删除操作只显示图标；模型设置在独立居中窗口中呈现，不占据表格空间或改变其他行的列宽。目录标题不显示自定义标记或恢复默认模型操作。空列表意味着「使用该路由的内置 catalog」，因此每一行都只会被刻意添加；清空容量会丢弃它，而不是存入一个 schema 会拒绝的值，配置留空的部分由适配器的路由级回退值定尺寸——留空的容量以这些回退值的量级作为占位符，那只是提示而非镜像：该字段按 1000 计 `K`，且部署可以覆盖这些回退值。不是正整数的容量根本不会被存下。

**获取可用模型**会针对表单**当前显示**的端点调用 `llm.discoverModels`，包括已修改但尚未保存的 API 地址和已键入但尚未存储的密钥，因此新增一个提供方是一趟走完，而不是「先保存再回来」。回复会打开选择框而非直接持久化：候选一律默认不勾选，已配置模型不可重复导入且其容量不被覆盖；搜索后的**全选**／**取消全选**只操作当前可见且未加入的候选，**添加所选**只采纳当前可见选中项。逐项或整组加号即时加入草稿后显示“已加入”并禁用重复导入；仍须保存渠道才会写入设置。无法被询问的提供方只是绕路而非死路——适配器自己的消息会显示在各行旁边，而这些行仍可手工编辑。

**添加渠道**表单声明 pi-ai 自定义路由。路由 id 在此选定，创建时一次 `settings.mutate` 在 `providers.<route>` 上设置整个 profile 并携带打开表单时的 revision，密钥经 `credentials.set` 单独传递，使用与既有提供方相同的 `<ROUTE>_API_KEY` 派生；并发修改会以 `settings-conflict` 拒绝，不能覆盖另一标签页的 profile。创建按钮要求唯一的 **Provider ID**、端点、协议，以及至少一个标识唯一的模型，错误在对应字段显示。该 id 必须以小写字母开头，因为它也是 POSIX shell 凭据引用的词干；容量可留空并使用适配器回退值。协议选项从 `llm-pi-ai` namespace 的 schema 读取，只有键入密钥时才记录 `apiKeyEnv` 引用，因此原生认证渠道不会指向未设置的密钥。profile 写入成功而密钥写入失败时，渠道已经存在，表单锁定 profile 字段并只重试凭据；此时取消、Escape 或遮罩关闭会刷新目录并选中已创建渠道，不会撤销 profile。

## 模型体验

无。该分区渲染浏览器配置 UI；这里没有任何内容进入模型请求。

无；该包既不组装也不发送提供方请求。

## 已知限制与暂缓事项

- **页面只编辑精选路由与模型字段**：两个家族公开 API 密钥、`baseURL`，模型的 `id`/`name`/`contextWindow`/`maxTokens`、视觉与推理能力；DeepSeek 还公开渠道名称，手工声明的 pi-ai 路由公开 `displayName` 与 `api`。重试策略、超时、DeepSeek 模型说明及其他进阶字段仍留在 `settings.yaml` 中；编辑器未展示的现有模型字段会保留。不带这些约定字段的 profile schema 只渲染提示，两套精选布局以 `llm-deepseek`/`llm-pi-ai` namespace 选择。
- **凭据清理范围刻意保持狭窄**：删除一行时，仅当其引用与页面派生的 `<ROUTE>_API_KEY` 目标完全一致，才会清除已配置且可写的凭据。自定义引用、环境凭据和无法识别的目标会保留，因为该行无法证明自己拥有它们。
- **只有 pi-ai 路由可以手工声明**：居中的添加渠道表单写入 `llm-pi-ai`——唯一一个其 profile 描述整个提供方的 namespace。`llm-deepseek` 路由与尚未配置的已安装目录渠道不能通过本页添加；已有配置仍可在列表中编辑。
- **询问只覆盖 OpenAI 兼容端点**：适配器只读这种模型列表响应格式，因此讲其他协议的网关会报告自己无法被询问，其模型需手工填写。
- **未声明的存活路由无处渲染**：未附带可配置提供方声明即注册的路由没有 settings 地址；它在各选择器中仍然可见，但不会出现在本页的行里。
