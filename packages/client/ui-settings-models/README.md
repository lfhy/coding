# coding-client-ui-settings-models

模型设置、视觉理解目标与首次使用模型配置引导插件。设置模态框左侧导航分别提供「模型」和「图片识别」，沿用[设置外壳](../ui-settings-general/README.md)的统一尺寸与导航：模型分区是可搜索的渠道中列加右侧渠道详情，窄屏时列表与详情互相返回；图片识别是独立设置分区。模型、图片识别、会话标题与首次引导共用一份从 `llm.providers`、唯一 `settings.describe` 镜像和不含密钥值的 `credentials.describe` 联接的快照，不显示路由存活状态，也不回显真实密钥。

首次引导渲染同一个模型分区，因此渠道列表、添加渠道表单与详情编辑器与设置页完全一致，只在底部额外选择默认模型。

## 渠道列表与详情

中列与搜索列出已有生效 profile 的可配置渠道，以及提供方插件自带的**内置渠道**（如 Free）；内置渠道没有设置分节，排在用户渠道之前并默认选中，只读展示它当前服务的模型与能力。缺少密钥、目录读取失败或路由不活跃都不会隐藏已有渠道，无密钥引用的原生认证配置也会保留。列表徽标只根据 `credentials.describe` 回答凭据是否已配置，不代表路由存活状态。

中列唯一的**添加渠道**按钮打开居中表单，分「渠道信息」和「模型配置」两个子标签页，内部渠道 ID 自动生成、不提供输入框。表单不先选提供方类型，创建的路由一律写进 `llm-pi-ai.providers`；存量 DeepSeek 渠道 `deepseek-official` 仍由 `llm-deepseek` 分节维护，只能编辑，不能这样新建。尚未配置的已安装目录渠道不提供添加入口；`llm-pi-ai` 分节未声明可选请求格式、设置只读或尚未就绪时按钮禁用。创建前取消、Escape 或点击遮罩只关闭表单，不改变当前选中渠道；创建成功后关闭表单并在右侧详情选中新渠道。

选中渠道后详情常显密钥、API 地址与模型目录；删除只适用于用户层独占的 profile，并在确认框中点名渠道。DeepSeek 官方渠道的整个设置分节就是 profile，因此默认条目仍可编辑，其渠道名称字段位于密钥旁：写入 `channelName`（默认 `DeepSeek`），列表、详情标题与未编辑的名称字段共用可配置目录的生效 `displayName`。只有用户编辑过名称时提交才写入去除首尾空白的覆盖，空名称或超过 64 个字符会在字段旁提示而不写入，显式输入 `default` 也合法；只改密钥或地址不会写入或规范化名称。名称只是这一条渠道的显示元数据，不创建路由，也不改变 `deepseek-official` 或凭据引用 `DEEPSEEK_API_KEY`。

详情的「高级设置」按渠道保存**模型请求 User-Agent**：留空跟随产品默认，取值限 1–256 个可打印 ASCII 字符且首尾不得为空格，非法值不提交。它只影响该渠道的对话与模型发现请求，不影响网页抓取或搜索请求；字段语义见 [llm-deepseek](../../llm/llm-deepseek/README.md) 与 [llm-pi-ai](../../llm/llm-pi-ai/README.md)。

## 请求格式

上游请求格式按拥有该字段的设置 schema 编辑三处：渠道 `api`、模型的 `models[].api`、已安装目录整行覆盖的 `modelOverrides[id].api`。schema 没有该字段时页面不显示控件，可选值也只取自该字段声明的联合。

模型的生效格式依次取 模型 `api` → 部署为单个模型固定的 `modelOverrides[id].api` → 渠道 `api` → 自动。自动对存量 DeepSeek 渠道和手工声明的 pi-ai 路由都是 OpenAI Chat Completions；已安装目录路由按目录提供的模型协议决定。菜单的空选项点名下层实际生效的格式：之下是组合配置的值时显示该值，否则显示自动。内置 Free 没有请求格式字段，其余可编辑渠道都有。

清除字段覆盖通常提交该路径的 `unset`，不写入空值；用户层 `models` 是整数组字段，目录具化时以完整数组 `set`，恢复继承时才对 `models` 提交 `unset`；创建渠道时选择自动则不写 `api`。协议的解析与落盘归适配器：见 [llm-deepseek 的请求格式与传输](../../llm/llm-deepseek/README.md#请求格式与传输)与 [llm-pi-ai 的目录解析](../../llm/llm-pi-ai/README.md#catalog-解析)。

## 出站

出站属于渠道，不在代理池分区。内置渠道的出站是它唯一可写字段，位于模型目录上方：直连／内置代理池／自定义代理的写入落在渠道插件自己拥有的分节（Free 渠道是 `llm-opencode`），经 `settings.mutate` 只提交 `mode` 与 `customUrl`，带该分节 revision；选择直连或内置池即保存，自定义模式须填 `http://` 或 `https://` 地址后才可应用。存量 DeepSeek 渠道的出站字段在详情的高级设置里，写入 `llm-deepseek` 的 `outbound`，随渠道保存一起提交。`llm-pi-ai` profile 没有出站字段。内置代理池受**设置 → 代理池**的池规则约束：池为直连时，这里选择内置池也按直连处理（[共享出站契约](../../net/proxy-pool/README.md#共享出站契约)）。

## 模型目录

模型目录以对齐的模型 ID、模型名称、视觉和推理列显示各行，后两列用状态图标区分已声明支持、不支持或未声明，详情区较窄时表头与行一起横向滚动。行尾图标打开屏幕中央独立的「模型设置」窗口，不插入模型行、不改变其他列宽，窗口自带取消和保存；窗口内保存只把本行改动纳入草稿，取消或关闭即丢弃，详情保存后才写入设置。已有模型的未知字段保留。窗口里的思考档位、上游请求格式和默认模式各占一整行并铺满行宽，继承文案较长时不会被相邻字段挤成窄条；上下文窗口与最大输出 token 两个数值输入并排。

视觉与推理字段按拥有该目录的 schema 决定形态：模态取 `inputModalities` 或 `input` 数组，推理档位按 schema 声明以字符串数组或「档位到协议拼写」的映射存储，schema 未声明的字段不显示也不推断。两者是带可访问按下状态的图标开关，开启推理后由共享悬浮菜单多选档位，触发框显示已选档位。DeepSeek 模型未单独声明推理档位时显示渠道策略的继承状态，pi-ai 缺少能力元数据时不推断；从手工添加或端点目录导入的模型按所属 schema 具化其模态和推理字段，渠道禁用 thinking 时 DeepSeek 只有 `off`。

每行承载模型 ID 与显示名称，上下文窗口与最大输出 token 收在同一窗口里，按数值键入并可带十进制的 `K` 或 `M` 后缀（`256K`、`1M`，即 1,000,000），存储为纯数值，回显成能往返的最短形式。空 ID、重复 ID、显式空名称，以及无法读取、非正数或非整数的容量都会在写入前失败。清空容量会丢弃该字段而不是存入被 schema 拒绝的值，留空容量以适配器回退值的量级作占位提示——它只是提示而非镜像，部署可以覆盖回退值。

`models` 是按值整体替换的数组：编辑器先显示继承而来的生效模型行，第一次模型编辑才把完整数组以用户层整数组 `set` 具化，重置（对 `models` 提交 `unset`）恢复继承。已安装目录的整行修改不换目录，只把改动字段写进 `modelOverrides[id]`；通过端点导入新增模型时，现有条目连同其覆盖一起具化为 `models` 数组。部署层已有非空 `modelOverrides` 时页面禁用目录导入并提示该限制；自定义渠道必须保留至少一个模型，带内置 catalog 的路由可以退回继承。

## 导入与端点询问

**获取可用模型**针对表单**当前显示**的端点调用 `llm.discoverModels`，包括已修改但尚未保存的地址和已键入但尚未存储的密钥，因此新增渠道可以一趟走完。部署层已有非空 `modelOverrides` 时，页面以 `catalogManaged` 限制禁用该导入动作；其他情况下回复在紧凑的 Modal 选择框中显示搜索、当前可见数／总数、可滚动的单层分组列表和底部取消／添加所选操作，不直接持久化：候选一律默认不勾选，已配置模型不可重复导入且其容量不被覆盖。搜索后的**全选**／**取消全选**只操作当前可见且未加入的候选，**添加所选**只采纳当前可见选中项。逐项或整组加号即时加入草稿后显示「已加入」并禁用重复导入，仍须保存渠道才写入设置。发现协议只返回 ID、名称与可选容量，无法给出真实能力类别，因此弹窗只按模型 ID 家族分组，不按猜测提供视觉／推理筛选；导入只修改当前草稿。无法被询问的提供方只是绕路而非死路——适配器自己的消息显示在各行旁边，这些行仍可手工编辑。

没有验证请求契约，因此页面不提供伪造成功状态的「检测」按钮。

## 写入与凭据

每一次编辑都以 `settings.mutate` 的路径 op 落到已存分节上：页面对可见字段提交最小 set/unset，用户层 `models` 例外地以完整数组 `set` 具化，恢复继承才对该字段使用 `unset`；删除提供方行则是单独一条 unset。页面自始至终只持有**脱敏后**的 descriptor，因此它只修改自己看得见的字段，而不重建分节。每次写入携带卡片当前的 `revision`，来自另一个标签页或对 `settings.yaml` 的外部编辑造成的并发写入会以 `settings-conflict` 被拒绝；提交成功后卡片采用应答的脱敏用户子树与 revision，并折入唯一设置镜像。凭据阶段失败时只重试凭据；保存完成后等待目录按新镜像联接再重挂载编辑器。删除只在 profile 指向页面派生的 `<ROUTE>_API_KEY`、且该凭据已配置可写时先清凭据再取消设置，两项操作都幂等，部分失败会停留在点名目标的确认框中供重试；环境凭据、自定义引用和无法识别目标的凭据保持不变。

键入的 API 密钥在它自己的字段上被判定：trim 之后必须非空，且每个字符都是可打印 ASCII（`[\x21-\x7E]`）——这正是 HTTP 标头值所能承载的范围，是 `coding-llm` 中 `normalizeApiKey` 的孪生体，因源码平面分割禁止直接引入而在此镜像。与整行粘贴的 `NAME=value` 环境变量匹配或首尾成对引号包裹的值会以同一条格式失败被拒绝，这项粘贴行检查只在浏览器中运行，因为 resolver 中的一次误判会连带让环境变量这条路也拒绝该密钥。只含空白的输入框会失败而不是被静默丢弃；留空则完全不是失败：在编辑卡片上意味着保持已存储的密钥，在新建卡片上意味着以其他方式鉴权。被拒绝的密钥同时拦截写入与端点探测，因此页面不会白花一次往返去换取字段上已经写明的答案。

创建渠道时每次草稿生成以小写字母开头、包含完整 UUID 的内部路由 ID，并避开目录路由及各设置层已占用的 profile 键；创建后该 ID 固定，修改显示名称不会改变请求、会话、默认模型或凭据使用的路由。最终确认以一次 `settings.mutate` 在 `providers.<route>` 上设置整个 profile，携带打开表单时的 revision，并发修改会以 `settings-conflict` 拒绝；密钥经 `credentials.set` 单独传递，使用 `<ROUTE>_API_KEY` 派生引用，只有键入密钥时才记录 `apiKeyEnv`，原生认证渠道不会指向未设置的密钥。profile 写入成功而密钥写入失败时渠道已经存在，表单返回「渠道信息」并聚焦密钥、锁定 profile 字段，「重试」只写凭据；此时取消、Escape 或遮罩关闭会刷新目录并选中已创建渠道，不撤销 profile。

页面加载完成后直接订阅转发的 owner 事件 `settings/document-updated`、`credentials/updated`、`llm/adapters-updated`，以及本地 `connection/reset`，因此外部的 `settings.yaml` 编辑、第二个标签页或 settings 新生的路由都无需轮询即可收敛。

## 首次引导

首次引导从同一个模型联接快照判断就绪：只有当前 `agent-default-model` 的提供方和模型出现在可启动目录候选中，步骤才直接完成且不渲染。首次判定期间不绘制弹窗，但临时将应用根节点设为 `inert` 以阻断工作台，确认已有可用默认模型后立即解除。候选来自已注册、活跃且配置可用的提供方及其成功读取的模型目录；具名凭据引用必须已配置，没有引用的提供方可使用原生认证。

没有可用默认模型时，弹窗保留模型分区的提供方编辑能力，要求先有可用提供方与至少一个目录模型，再在底部选定默认模型并保存；不能跳过，也不能通过遮罩或 Escape 关闭。配置通过 `settings.mutate` 保存，引用式凭据的密钥仍只经 `credentials.set` 写入。设置只读、凭据不可用或模型目录读取失败时保留弹窗并显示诊断与重试，不能把未知状态当成完成；用户显式重试会先重读共享设置镜像，再重新联接提供方、凭据与模型目录。

## 图片识别与会话标题

图片识别分区在 `vision-understanding` 分节可用时显示目标选择，候选只来自 `llm.models` 中已配置、可用且明确声明 `inputModalities` 含 `image` 的模型。默认不选，选择或清空都以同一次 `settings.mutate` 对 `provider`、`model` 成对写入或删除，带该分节 revision，并将应答折回共享设置镜像。已保存但不在当前候选内的目标会显式保留供清空或替换；目录整体读取失败或已配置可用渠道逐项失败时，保留渠道、已存目标及其他渠道成功返回的候选，展示诊断和重试，且不把已存目标推断为不可用。不可用渠道的目录失败不影响视觉目标，只有成功读取后没有候选才显示空候选提示；只读、整体加载失败和分节缺失也有可见状态。纯文本模型遇到图片时使用该路由生成描述，未配置路由会提示不支持，不把模型 ID 或端点发现结果当成视觉能力证明。

会话标题一行在 `session-title` 分节可用时显示标题模型模式：继承主模型、自定义模型或关闭标题生成。自定义模式下再列出标题模型路由，候选是同一份可用模型目录里的全部模型（不按图片能力筛选）；切换到自定义但尚无路由时先展开模型选择，选中的模型与模式在同一次 `settings.mutate` 里写入 `mode`、`provider`、`model`，其余模式写入 `mode` 并删除残留路由。分节缺失、设置只读与写入失败都有可见状态。标题模型只影响新会话标题的生成，不改变对话模型与既有标题。

模型行可选默认 Agent 模式，未选则实时继承 `agent-presets` 的全局默认；它保存在 `agent-presets.modelDefaults` 的提供方／模型映射，而非适配器的推理配置。新建会话的显式模式优先于模型默认，已有会话切换模型不改变模式。

## Model Experience

### Request context and condition

#### What the model sees

无。该分区渲染浏览器配置 UI，不向模型请求加入内容。

无直接 token 影响。

无；该包既不组装也不发送提供方请求。

## Known Limitations and Deferred Work

- **页面只编辑精选字段**：两个家族都公开 API 密钥、`baseURL`、渠道与模型的请求格式和渠道级 `userAgent`，DeepSeek 另有 `channelName` 与出站，手工声明的 pi-ai 路由另有 `displayName`；模型行公开 `id`、`name`、`contextWindow`、`maxTokens`、视觉与推理能力和默认 Agent 模式。重试策略、超时、`compat`、图片上限及其他进阶字段仍只能在 `settings.yaml` 里设置；编辑器未展示的现有模型字段会保留。
- **导入目录与部署的 `modelOverrides` 不能共存**：在已安装目录路由上，部署层已有非空 `modelOverrides` 时页面以 `catalogManaged` 限制禁用目录导入；若通过其他入口让整份 `models` 数组与 `modelOverrides` 共存，Host 会拒绝该 profile。
- **凭据清理范围刻意保持狭窄**：删除一行时，仅当其引用与页面派生的 `<ROUTE>_API_KEY` 目标完全一致，才会清除已配置且可写的凭据。自定义引用、环境凭据和无法识别的目标会保留，因为该行无法证明自己拥有它们。
- **只有 pi-ai 路由可以手工声明**：居中的添加渠道表单写入 `llm-pi-ai`——唯一一个其 profile 描述整个提供方的 namespace。`llm-deepseek` 路由、内置渠道与尚未配置的已安装目录渠道不能通过本页添加；已有配置仍可在列表中编辑。
- **询问只覆盖已注册发现与 OpenAI 兼容端点**：适配器只读这种模型列表响应格式，因此讲其他协议的网关会报告自己无法被询问，未注册模型发现的 namespace 报告没有发现，其模型需手工填写；内置渠道不提供发现入口。
- **内置渠道没有编辑能力**：不带可配置提供方声明的存活路由按只读卡片展示，页面不提供改端点、换密钥或改目录的入口；这些事实由提供方插件随应用发布。
