# coding-ppt-model

## 概述

PPT 工程的数据模型与校验：演示文稿（`PptDeck`）、页面（`PptPage`）、元素（`PptElement`）、主题配色与画布尺寸，以及把外部 JSON 收成合法工程的 `parseDeck`。

宿主（`coding-ppt-workbench`）与浏览器（`coding-client-ui-ppt-workbench`）是两个独立的 TypeScript 程序，二者对「什么是一份合法工程」的判定必须一致；这个包就是那份共同定义。它只做纯数据与纯函数：没有 IO、没有 React、没有 Cordis 服务，因此既能进宿主图，也能被打进浏览器半。

## 契约

- **坐标**：以基准像素表示，16:9 为 1280×720，4:3 为 960×720，原点在左上角。导出时按 96 DPI 换算（1 像素 = 9525 EMU），所以面板上的位置就是 .pptx 里的位置。
- **颜色**：一律 `#rrggbb`。页面 `background` 为 `null` 时取主题底色，换主题即可整体换色。
- **元素**：`text`（带字号、颜色、加粗、对齐与垂直对齐）、`rect` / `ellipse`（填充色）、`line`（颜色与线宽）、`image`（工程内 `media/<file>` 与 `cover`／`contain`）、`table`（行 × 列、列宽权重、表头配色与共享排版）。数组顺序即绘制顺序，后面的盖住前面的。
- **页面**：名称、底色（`null` 用主题色）与转场（`none` / `fade` / `push`）。
- **规模上限**：一页最多 200 个元素，一份文稿最多 200 页，单段文字最多 5000 字符。超限直接拒绝，不静默裁剪。
- **失败**：`parseDeck`、`parseElement`、`parsePage` 在结构不合法时抛 `PptModelError`，消息指名到字段（例如 `pages[2].elements[0].text.size 必须在 6 到 400 之间`）。

## 使用本包

宿主与浏览器半都直接 import 类型与校验函数。写入磁盘、通过 HTTP 返回或模型生成的内容都必须先过 `parseDeck`，这是唯一的准入点；同进程内已经由类型保证的值不需要再校验一次。

## 模型体验

无。本包不注册工具、不组装提示词，也没有任何内容进入会话日志。

#### KV Cache 影响

无；本包不发送提供方请求。

## 已知限制与暂缓工作

- 不支持图表、SmartArt 与动画：它们无法用当前元素集合表达，导入时会被列为 `dropped`。
- 图片只按 `media/<file>` 引用，模型里不存字节；读取与嵌入由宿主与导出负责。
- 主题只有四套内置配色，不支持用户自定义主题文件。
- 校验只覆盖结构与数值范围，不做版式层面的检查（文字是否会溢出文本框、元素是否互相遮挡），这类判断留给调用方。
