# coding-tool-status

提供模型工具 `set_status`，报告当前工作进度。每次成功调用向所属会话追加全量 `status/set` 事实，不修改待办、目标或消息正文。工具在基础组合的 Host 层提供，各模式共用，子代理只写自己的会话。

## 行为与投影

`set_status({ text })` 接受一句用户语言的短进度，去掉首尾空白后必须非空、单行、不含控制或格式字符，最多 120 个 Unicode 码点。`text: null` 清除手动进度。没有所属 Agent、没有开放轮次、已取消或文本不合法时失败且不追加事件；写入按工具独占执行顺序提交。

手动进度持续到本轮再次设置、显式清除、下一次待办更新或轮次结束；`todo/write`、新的 `turn/start` 与 `turn/end` 均清空。可选 `ctx.sessionProjections` 注册 `turnStatus: string | null`，从日志恢复后仍是同一轮的最新进度，过时轮次的事件不会恢复覆盖。投影缓存版本为 `1`。卸载插件同时移除工具与投影。

客户端按手动进度、进行中待办、活跃目标、随机短语依次选择运行文案。更新待办会自动撤销已有手动覆盖，立即显示最新进行中任务；之后再次调用 `set_status` 才重新使用手动进度。没有进行中任务时回退到活跃目标或随机短语；本包不计算这套展示优先级。

## 模型体验

### 进度报告

#### 模型看到的内容

工具说明要求在有实质进展或方向变化时提供简短进度，不要求每次调用前报告，不允许写入内部指令、代码、原始错误或凭据。成功设置返回 `Current progress: <text>`，清除返回 `Automatic progress restored.`；规范输出为 `{ text: string | null }`。工具调用及结果保留在历史中，独立的进度事实不进入模型消息正文。

#### Token 影响

固定增加一个工具 schema；每次调用追加短参数与一条短结果。自动跟随待办或目标不产生额外模型请求。

#### KV Cache 影响

工具 schema 稳定；调用历史只追加，不随进度变化改写已有请求前缀。

## 已知限制与暂缓事项

- 不验证模型报告是否真实，也不代替最终答复或需要用户决策的问题。
- 不保留跨轮次手动覆盖；没有开放轮次时不能预设下一轮进度。
