# @deepseek-ai/dsh-tool-memory

把当前会话所属项目的记忆交给模型读写的四个工具。参数里没有任何路径：目标永远是会话项目根对应的记忆目录，因此模型读写不到别的项目的记忆。

## 工具

| 工具 | 作用 |
| --- | --- |
| `memory_save` | 往目标记忆文件的指定小节追加一条持久要点（默认 `notes.md` 的 `要点`），写入前执行服务层的四项限额 |
| `memory_read` | 读取一个记忆文件全文；会话基线只带摘要，细节靠这里补齐 |
| `memory_list` | 列出该项目的记忆文件（名称、标题、字节数、最近修改时间） |
| `memory_delete` | 删除整个文件或其中一个小节；只在用户要求遗忘或条目确已过期时使用 |

四个工具的 schema 见生成的[工具目录](../../../docs/tool-catalog.md)；本包只补充那里的落地差异：目标项目由会话 cwd 决定，`file` 参数只是文件名白名单内的一级文件名，`section` 是小节标题。

## 隔离

`inject = ['tools', 'memory']`，因此只有同时挂载了工具注册表与记忆 Provider 的组合才会激活这些工具。每次调用都用 `exec.agent.session.header.cwd` 解析项目身份；没有所属会话的调用方（例如直接执行工具的宿主脚本）会被拒绝，而不是落到某个猜测出来的目录。文件名由服务层校验（`[a-z0-9._-]+\.md`、不含路径分隔符），所以 `file` 参数也无法越出项目目录。

## 配置

无配置项：限额、默认文件与默认小节都属于 [`@deepseek-ai/dsh-memory`](../memory/README.md) 的策略，部署在那里调整。

## 模型体验

### 记忆工具 schema

#### 模型看到的内容

四个工具的名称、描述、参数与结果 schema 见[工具目录](../../../docs/tool-catalog.md)。描述里写明了记忆的性质：它是用户数据主目录下这个项目自己的笔记、跨会话保留但不属于仓库；值得记的是用户偏好、这个仓库里非显然的约定、踩过的坑与结论、跨任务待办；凭据与代码里已写明的内容不记。

#### Token 影响

每次请求都重复四个工具的 schema。`memory_read` 的结果受服务层单文件上限约束（默认 64 KiB），`memory_list` 的条目数受每项目文件数上限约束（默认 16）。

#### KV Cache 影响

仅追加：工具结果进入历史，不影响此前的可复用前缀。

## 已知限制与暂缓事项

- **没有跨项目检索**：工具只看见当前项目，这是有意的隔离设计；跨项目复用要点需要用户自己复制。
- **不做并发合并**：两个会话同时写同一文件时后写覆盖先写（见 Provider README）。
- **删除不需要二次确认**：审批策略由部署的审批栈决定，本包不额外加确认步骤。
