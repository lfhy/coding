# coding-progress-reminder

长任务的进度提醒上下文。一个轮次内连续完成的工具调用达到阈值而模型始终没有向用户说话时，循环在下一次模型请求前注入一条系统提醒，要求在回复正文简短汇报进度后继续执行；只有确实存在用户选择或确认时才提问，没有决策项时不额外打断。Coding 组合默认启用它，节奏由 `toolCallsPerReminder` 控制。

## 配置

```yaml
- id: progress-reminder
  name: 'coding-progress-reminder'
  config:
    toolCallsPerReminder: 15 # optional; omit for the shipped default
```

`toolCallsPerReminder` 是未输出正文时连续完成工具调用的提醒阈值，默认 `15`，必须是正的安全整数；其他值在插件加载时失败。计数单位是一次已完成的工具调用（一条 `tool/result` 事件），不是模型调用的轮次，所以一次并行批次可以跨过阈值，提醒文本会写出真实的累计数。

## 计数与注入时序

插件追加一个 `agent/pre-step` 监听器，先行委托下游，再把提醒追加到将要进入步骤的消息批次末尾。因此提醒与它所属的请求同批写入日志，被下游拒绝、监听器失败或轮次信号已中止时不会留下任何记录。

计数完全从会话日志派生：从尾部回扫，遇到本插件上一次注入的提醒、上一个轮次的 `turn/end`，或包含至少一个经 `trim()` 后非空 `text` 块的 `assistant/message` 就停止，统计区间内已完成的 `tool/result` 数。仅含推理块（`reasoning`）、工具调用或空/空白 `text` 块的消息不重置计数；同一条助手消息同时包含正文与工具调用时也重置计数，其后的 `tool/result` 重新累计。

插件不持有进程内状态，所以恢复、fork 与压缩遮蔽后的计数一致，不会因为漏记一次分发而少提醒或多提醒。轮次边界同时是计数边界：下一个轮次从头累计。

提醒是持久的用户消息（来源 `{ kind: 'plugin', plugin: 'progress-reminder' }`），会留在派生历史中直到压缩遮蔽。`./invariant` 配套模块校验每条提醒的文本逐字等于渲染结果，且声明的调用数等于该边界之后的真实计数。

## 模型体验

### 连续工具调用后的进度提醒

#### 模型看到的内容

提醒是一条 `<system-reminder>` 区块，插在触发它的那次工具结果之后、下一次请求之前。`<tool-calls>` 是该边界之后真实完成的工具调用数。本提醒只对紧邻的下一次助手回复生效：模型应在该回复正文简短汇报一次已完成和剩余工作，之后继续执行；后续步骤不需要逐步重复汇报。除非之后收到一条新的本提醒，或确实需要用户选择或确认，否则按原计划继续，不为了满足提醒而额外询问；任务完成时按正常方式向用户报告结果。

##### 提醒文本

```markdown
<system-reminder>
你已连续执行 <tool-calls> 次工具调用，其间没有向用户汇报过进展。
这是一次性提示，只对紧邻的下一次助手回复生效；它不是持续规则，也不是每个步骤的固定要求。
请在紧邻的下一次回复正文中简短说明已完成什么、还剩什么，然后继续执行。说明一次即可；处理完这条提示后，即使历史中仍能看到它，也不要在每次工具调用或后续步骤前重复汇报。
除非之后再次收到一条新的本提醒，或确实需要用户选择或确认，否则按原计划继续，不要为了汇报而停下或提问。任务完成时按正常方式向用户报告结果。
</system-reminder>
```

#### Token 影响

每条提醒只注入一次，并保留在请求历史中直到压缩将其遮蔽；典型轮次只有一到两条。

#### KV Cache 影响

仅追加；新可见内容位于可复用请求前缀之后，不会使现有 KV Cache 条目失效。

## 已知限制与暂缓事项

- **只提醒，不强制**：提醒是模型可见的指令，模型可以不汇报而直接继续调用工具；本包不做回复拦截或轮次中断。
- **不校验汇报内容**：插件只用非空正文判断计数是否重置，不判断正文是否包含有效进展，也不校验或补写汇报内容；仅在推理块中汇报不重置计数。
- **提醒不代替用户决策**：没有实际选择或确认事项时，模型应继续执行；插件不强制插入问题，也不判断任务是否需要用户决策。
- **按会话阈值固定**：阈值是插件配置，不是逐会话或逐轮次的覆盖；同一 Host 上的所有 agent 共用它。
- **不区分工具**：任何已完成的工具调用都计数，包括快速只读查询；需要精细节奏时用触发工具的部署组合自行调整阈值。
