# coding-skill-project-init

随包分发 [`project-init`](../../../README.md) 技能：在改动业务代码之前建立可回滚的版本基线。插件依赖 `ctx.skills`，无配置；正文是 [`assets/project-init.md`](assets/project-init.md)，资源目录同时交给消费方定位。卸载即撤销登记。

技能面向三类时机：在空目录开始新项目、用户要求某次改动「可回滚」、以及在一个还不是 Git 工作区的项目里动手实现。正文要求先用 `git rev-parse --show-toplevel` 判断现状（父级仓库与 worktree 都算已在工作区），不在工作区时才 `git init -b main`；随后写 `.gitignore`，逐条确认要纳入版本的文件并用具体路径 `git add`，最后建一条基线提交作为回退锚点。之后每一步改动按「改一处 → 跑覆盖该处的验证 → 一个本地提交」推进，不推送、不改写历史、不切分支。

正文同时给出新项目的最小文件集（`README.md` 说明做什么与怎么运行，`AGENTS.md` 说明结构、命令、约定与安全边界，项目变大后再加代码地图），并明确三条禁止：不在工作目录之外初始化仓库、不在已有仓库里建嵌套仓库、不提交凭据与构建产物。用户明确不要 Git 时正文要求照办并说明代价。

它不做别的事：不删除或覆盖用户已有文件，不改 `.gitignore` 之外的配置，不代替用户决定推送与分支策略；这些判断留给会话里的用户指令与项目约定。

## Model Experience

### 技能目录与正文

#### What the model sees

目录贡献的名称为 `project-init`，描述为：

> 在新建项目、空目录或需要让改动可回滚时使用：先确认是否已在 Git 工作区内，未初始化就 git init、写 .gitignore、逐条确认后建基线提交，并给出新项目最小的 README／AGENTS；之后每一步改动都小步验证并本地提交。

被选择时加载的固定正文见 [`assets/project-init.md`](assets/project-init.md)。技能允许模型从目录加载，也允许用户显式调用。

#### Token effect

启用后目录增加一项固定描述；仅在模型或用户加载该技能时加入正文。正文不含随仓库变化的内容，加载后的大小固定。

#### KV Cache effect

固定目录条目改变目录所在请求前缀；加载正文后，该轮请求增加固定指引。技能启用状态或目录成员变化可能改变前缀。

## Known Limitations and Deferred Work

- 技能只给操作顺序与判断标准，不能代替执行：初始化、忽略规则与提交仍由模型用 Shell 与 Git 工具完成，权限与审批沿用会话设置。
- 不覆盖非 Git 的版本控制方案；使用其他 VCS 的项目只能在正文之外按其约定处理。
