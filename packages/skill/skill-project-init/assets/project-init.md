# 初始化本地仓库与项目基线

用户要在当前目录开始一个新项目、或要求把改动做成可回滚时，先把地基与版本基线定下来，再动业务代码。已经在一个 Git 工作区里（包括父级仓库与 worktree）就不要重复初始化。

## 确认现状

用 `git rev-parse --show-toplevel` 判断当前目录属于哪个工作区：返回路径说明已在仓库内，可能只是某个父级仓库，此时不要 `git init`，直接看「之后的每一步」。命令失败才说明不在任何工作区里。

同时看清目录里已经有什么：`ls -a`，以及有 `.git` 时的 `git status --porcelain`。用户已有的文件保留，不要为了「干净」删除或覆盖。

## 新项目先找现成的地基

目录是空的、或只有需求、说明文档和零散草稿，就是新项目。同时满足下面三条时，不要从空文件开始手搭：

- 当前会话能联网：有 `web_search`／`web_fetch`、浏览器工具，或能在 Shell 里联网 `git clone`。
- 用户没有要求完全从 0 开发、不引入现成代码，或自己重写框架底层。
- 用户没有指定必须用某个脚手架；指定了就按指定的来，只在它里面挑模板。

搜 GitHub 按下面的优先级进行，找到能用的就停下，并告诉用户用了哪个仓库：

1. **template 仓库优先。** 搜与需求同栈的模板或脚手架，例如 `site:github.com <技术栈> template`、`<技术栈> starter`、`awesome <技术栈> templates`。挑最近仍在提交、README 写清安装与启动、LICENSE 明确的那一个，它的目录结构就是本项目的地基。
2. **其次找同类项目做参考。** 没有可用模板时再搜已经做成同类产品的仓库：后台管理系统先看 `vue-vben-admin`（vben）、`shadcn-admin` 这类成熟管理后台模版及其衍生项目，仍不够再找同领域的业务仓库。只借目录结构、路由与状态管理、鉴权、表格与表单抽象，不整块搬业务代码。
3. **两者都找不到**才从零搭，并在回复里说明搜过但没有可用的现成方案。

落地模板时用 `npx degit <owner>/<repo>`，或 `git clone --depth 1` 到临时目录再把内容拷进当前目录，不要留下模板自己的 `.git`，使当前目录成为模板原状而不是嵌套仓库。先跑通模板自带的安装与启动命令，再改业务代码；在 `README.md` 里写明模板来源仓库、版本或 commit、许可证和本地改动范围，许可证要求保留声明时照办，不删它的 LICENSE 与署名。

## 后端按分层技能自己搭

后端不靠抄模板的目录结构定型：按已加载的分层技能搭。Go 服务端用 `go-backend` 的 `cmd/<binary>/` 加 `internal/<domain>/` 分层，以及其中 HTTP、context、错误包装、数据访问与测试的默认约定。模板与参考仓库只决定前端地基和业务形状，分层与依赖选择以技能和项目已有做法为准。

## 建立基线

1. 选分支名：默认 `main`，用户指定就按用户说的；`git init -b main`。
2. 写 `.gitignore`：按技术栈排除依赖目录、构建产物、缓存、日志、本地数据库文件、`.env` 与一切凭据。用户已有忽略文件时先读再补，不覆盖。
3. 逐个确认要纳入版本的文件：逐条看 `git status --porcelain`，用具体路径 `git add <path>`，不要 `git add .`。大文件、二进制、抓到的数据包先问清楚是否要进版本库。
4. 建基线提交：一条说明「记录当前状态」的提交，作为之后每一步都能回退的锚点。
5. 告诉用户基线提交的哈希，以及它包含哪些文件、哪些被忽略了。

用了模板时，先把模板落地并跑通，再把它的原状当基线提交；之后的提交才是本项目自己的改动，回退时能干净地退回模板状态。

## 之后的每一步

改一处 → 跑覆盖这处的验证 → 一个本地提交。提交前看 `git diff --cached`，不要把无关文件带进来。用户没要求就不要推送、不要改写历史、不要新建或切换分支。

## 新项目的最小文件

- `README.md`：项目做什么、怎么安装与运行、核心功能与已知限制。
- `AGENTS.md`：目录结构、实际技术栈、安装／运行／测试／构建命令、编码约定与安全边界。
- 项目变大后再加代码地图（例如 `docs/codemap/README.md`）并从 `AGENTS.md` 链接。

这些文件已存在时先读后补，保留用户内容；只写在这个环境里实际验证过的命令。

## 不要做的

- 不在工作目录之外初始化仓库，不在已有仓库里建嵌套仓库。
- 不提交凭据、令牌、会话数据、缓存与构建产物。
- 用户明确不要 Git 时照办，但要说清代价：没有基线，任何改动都无法回滚。

## 验收

`git status` 干净、`git log --oneline -1` 有基线提交、`.gitignore` 覆盖了构建产物与凭据；用了模板时还要能在 `README.md` 里查到来源与许可证。把这几条写进回复，没做到的部分说明原因。
